# Ysello 2026-09-09.2

This full source ZIP contains the preceding 2026-09-09.1 Telegram patch plus the fixes below. Based on the latest saved 2026-09-08.6 project, not a fetched GitHub head. No live deployment or supplier account change was performed. GitHub access must be connected before comparing and pushing to Imtiaz6228/ysello.

## Visitor notifications

Known bots and HTTP page requests remain excluded. A signed visitor session now binds the engagement request to the originating IP/user agent and enforces a minimum 35-second age on the server. Tampered, expired and different-client tokens are rejected. The browser still requires visible browsing and a trusted interaction. Thus a caller cannot send a single fabricated dwell-time report immediately to trigger an alert. Sophisticated browser automation can still imitate human behavior; this is a likely-human filter, not proof of identity.

The main-bot fallback, order/top-up alerts, top-up approval/rejection alerts, and duplicate visitor suppression from 2026-09-09.1 remain. Visitor deduplication is per API process and resets on restart. No live Telegram messages were sent in testing.

## SHOP2TOPUP imports

- Select-all imports are split into batches of at most 50, matching the server limit. A 120-item selection is sent as 50/50/20. Progress is shown; failed and unprocessed IDs remain selected for retry.
- Validated supplier responses now distinguish malformed data from a legitimate empty catalog. Invalid HTML/JSON and missing arrays produce an actionable error instead of appearing as zero products.
- An empty image-enabled group/category response is retried with the documented for_ui=false option. Authentication and disabled-account failures are not bypassed.
- Identical catalog reads share requests and have a bounded 30-second cache to reduce supplier rate-limit pressure. Price endpoint reads are not cached.
- Numeric item/category identifiers are normalized, and items from a different selected category are excluded.
- Requirements retrieval failures are no longer silently replaced with an empty list.
- Automatic category mapping cannot assign a category as its own parent when group and category names collide.
- Initial empty catalog loading now reports the empty state explicitly.

Product import preserves the existing draft policy. Supplier player/server/account fields and automated fulfillment are not yet connected to buyer checkout in this baseline. These products are therefore not published or made purchasable by this patch. A disabled/frozen supplier account, invalid key, or IP allowlist denial requires resolution with SHOP2TOPUP or the deployment configuration. No actual supplier catalog was imported into the live database during this work.

The API paths, parameters and response schemas were checked against the official catalog reference:
https://shop2topup.com/en/reseller-api/docs/catalog
