# Ysello release 2026-09-05.6

This package contains the updated source, built frontend and built API. It has not been deployed to your Vercel/Railway services or tested against your production database.

## What changed

- A platform classifier places recognized Dark Shopping imports into Facebook, Instagram, Gmail, Telegram and other platform categories. It distinguishes the account being sold from an included email address. Unrecognized products retain a general supplier category for review.
- Existing imported products are repaired at API startup. An authenticated administrator can also use **Supplier imports → Repair categories & images**. This operation changes category/platform/artwork; it does not alter orders, payments or delivered credentials.
- Navbar and homepage category lists use populated live categories. Facebook and Instagram aliases no longer point to one another. Category and catalog pages share the same filters and real server pagination: 50 products, numbered pages, and access beyond the old 500-product limit.
- Twenty-six bundled platform SVG icons supply consistent desktop and mobile product artwork without external image-CDN dependencies. Ysello Official has a bundled logo and store banner.
- Header, catalog controls, product artwork, store layout and all three workspace shells have been refined. Primary buyer, seller and admin navigation is shorter and grouped, with secondary tools retained in a separate selector.
- Main storefront and dashboard headings/navigation have Chinese and Russian translations. Language selection persists through navigation. Stored product-title translations are used in product lists, product pages and crawlable server HTML.
- A background worker translates missing approved-product titles and short descriptions into English, Simplified Chinese and Russian. It preserves existing seller translations and refreshes its own translations when source content changes. Stock synchronization no longer clears translations. Admin supplier imports shows progress, errors and retry controls.
- Product/category/catalog routes, sitemap and robots are forwarded to the backend. Legacy static demo category/product exports are removed from builds. Public HTML includes live product links, language annotations, canonical pagination and language alternatives. Sitemaps include localized URLs and split large inventories into sitemap pages.

## Deploy in this order

1. Deploy this full project to Railway using the existing production build/start commands. Preserve your current database, supplier, payment, email and authentication environment variables. Set **APP_URL=https://ysello.com** (or your actual public canonical domain), not the Railway/API hostname.
2. Wait for the API to become healthy. Startup repairs existing supplier classifications. Review the API log and a sample from each populated platform category.
3. Deploy the same release to Vercel. The supplied rewrites retain **https://api.ysello.com** as the backend; it must resolve to the Railway service. Both deployments must use this release. The backend supplies matching frontend assets for its HTML.
4. In **Admin → Supplier imports**, let the title-translation pass complete. If failures are reported, restore translation-service connectivity and use **Retry missing translations**. The worker uses the translation endpoint already present in this project; availability is not guaranteed. Missing translations display the original title until a successful pass. Review machine-translated titles before marketing campaigns. Arbitrary seller-written descriptions and policy text are not fully translated by this update.
5. Verify live desktop/mobile category navigation, page 2, product images, store banner, the three account roles, and one normal checkout in your established test workflow. Check Chinese and Russian URLs directly in a new session, including product titles in page source. Live supplier, payment and database integrations were not exercised in this workspace, and visual browser QA was not performed.
6. Submit the public sitemap in your Google, Bing, Yandex and Baidu webmaster accounts after domain verification. Indexing, rankings and mainland-China network performance depend on the live service and each search engine; code alone cannot guarantee them. Test your actual site from your target regions before launch.
