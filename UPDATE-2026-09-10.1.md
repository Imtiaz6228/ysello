# Ysello 2026-09-10.1

Based on the previously delivered 2026-09-09.2 source. These notes supersede earlier visitor timing and default-language instructions.

## Visitor timing

The browser now sends after 35 seconds of visible public-page browsing, including passive reading. A click is not required. Page changes no longer restart the tracking effect. Background/private-page time does not count. Tracking uses elapsed time rather than counting one second per interval. Retries are three seconds apart instead of fifteen seconds.

Signed sessions mature after 30 seconds so the normal 35-second browser notification does not race the server's timer. Tokens bind to the browser user agent instead of an IP that can change on mobile or through proxies. Expired/invalid tokens can be refreshed, while valid but immature tokens are retained. Known crawler user agents and navigator.webdriver automation remain excluded. This is an engagement estimate; sophisticated automation can imitate a human.

Geo lookup has an 800ms budget so it cannot add several seconds before sending. Missing country may appear as Unknown if neither trusted deployment headers nor the lookup supply it. Telegram/network latency can still delay delivery beyond the 35-second browser trigger. Repeated visitors are suppressed for 30 minutes by default. Local storage failures cannot cause a continuous stream of successful notifications.

## Order and top-up alerts

Order creation, wallet purchases, payment confirmations, top-up creation, proof submissions, and top-up approval/rejection are already connected to the corresponding saved events. They do not wait for the visitor timer. The existing main-bot fallback is preserved. Geo lookup now has an 800ms budget for order/top-up messages too. Tests cover saved order package/count/amount content and new top-up username content without a visitor session.

These notifications remain best-effort asynchronous tasks. Provider failures are logged; there is no durable outbox across server restarts. No live messages, purchases or balance changes were performed during this update.

## Category and product artwork

Removed hashtag icon fallbacks from category/platform icon components. Recognized category platforms now take priority over a stale generic remote image. X account slugs and nested platform categories resolve their brand. Unknown categories use a neutral layered icon; unknown products retain the existing Ysello image fallback. Known platform artwork retains existing official-color styling.

## Chinese storefront and search discovery

Default public server HTML and first-visit browser locale are Simplified Chinese. Default currency is CNY. Saved preferences and explicit language selection remain available; explicit English links now use ?lang=en so they do not collide with the Chinese default. Chinese URLs use ?lang=zh-CN and Russian URLs use ?lang=ru. Canonical/hreflang tags and runtime sitemap language entries agree. The same language behavior applies to visitors and crawlers; there is no special hidden Baidu storefront.

Chinese product pages use CNY in visible content and Product offers. Homepage/category server-rendered product lists now include localized prices. Existing CNY prices are used when supplied; otherwise the existing application conversion of 7.24 CNY/USD is retained, matching the browser's conversion. This is a configured display conversion, not a live exchange-rate feed.

Removed saved-English fallback from Chinese product mapping. Added Chinese translations for common product attributes and server-rendered store headings. Existing saved Chinese product titles are preserved. The background title/summary translation worker now prioritizes Chinese and saves successful languages even if another language fails. Complete translation of arbitrary supplier text depends on the external translation service and will run against the live catalog after deployment. No live database titles were rewritten in this session. Sitemap modification date is 2026-09-10. Indexing and ranking are not guaranteed.

SHOP2TOPUP import fixes from the preceding build remain. That supplier's products still import as drafts: buyer-side dynamic fields and automated fulfillment are not implemented by this notification/localization update. Supplier-disabled accounts still require supplier activation.
