# Ysello storefront update — 2026-09-05.5

This archive contains the updated website source, a locally verified web/API build, and deployment configuration. It updates the existing Railway/Vercel application. It has not been deployed to your live accounts.

## Storefront changes

- New Ysello homepage with a compact white/navy hero, platform links, category grid, account listings, collection banners, product cards, storefronts, shopping guide and help section.
- Imported categories appear in the shared navbar with their real category URLs. Mobile shortcuts use a wrapping grid; All categories expands vertically.
- Platform artwork uses bundled vector icons, including social networks, Gmail, Outlook, Yahoo, Proton Mail, ChatGPT, Claude, Gemini, Netflix and Spotify. Icons do not depend on third-party image CDNs.
- Store cards display uploaded banners and logos. Official stores have a Ysello logo fallback; missing banners retain a branded cover with the store name.
- Buy now adds the product at its minimum quantity and opens the cart for review. Purchases below the minimum available stock are disabled.
- Catalog loading, empty and API-error messages are distinct. No demonstration products or invented sales figures were added.
- Removed repetitive homepage product rails and the local-only newsletter success form. Existing account, seller, checkout, support and administration routes remain available.

## Import workflow

1. Deploy the frontend and Railway backend from this same archive. Both now expect release `2026-09-05.5`.
2. Open Admin → Suppliers and load products for a supplier category or search.
3. Use Select eligible page or Select all matching pages. More than 30 products can be selected; imports continue in sequential batches of 25, within the server request limit.
4. Leave “Match each product to its supplier category automatically” enabled to import/reuse the corresponding Ysello category for each product. Disable it only when you want all selected products placed in your chosen destination category.
5. Review the publish checkbox, then Import. Failed or skipped IDs remain selected for retry. Successfully imported IDs are removed from the selection.
6. Reload the storefront to see published products and categories. Draft products remain unpublished.

Changing the supplier category or search clears the old selection, preventing accidental carryover. Repeated supplier pages stop with an error; successfully loaded selections remain available. All-page selection has a 500-page bound: narrow the category or search if that guard is reached. Manual-delivery products and minimum orders above the existing 20-item checkout limit remain unsupported. Supplier access and stock still depend on Dark Shopping.

## Deploy the update

- Extract into the root of your existing Ysello source project and commit the changed source files to the repository connected to Railway and Vercel. Keep your existing production environment variables.
- Railway: use the existing `npm run build:railway` build command and `npm start` start command. Redeploy the backend from this commit.
- Vercel: redeploy the frontend from the same commit using its existing configuration and environment variables.
- Rebuild on your hosting provider; the included `dist` and `dist-api` folders are verification artifacts and do not contain hosting-specific environment settings.
- The release check in Admin → Suppliers should show `2026-09-05.5` for the backend. A frontend/backend mismatch blocks imports and requires redeployment of the older service.
- No new database migration was introduced by this update; retain the existing migration/startup flow. Do not reset the database or replace production secrets.
